# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

### Данные

#### Интерфейс IProduct
Описывает структору данных продукта.

Поля интерфейса:
  id: string; - Уникальный идентификатор товара
  description: string; - Описание товара
  image: string; - Картинка товара
  title: string; - Название товара
  category: string; - Категория товара
  price: number | null; - Стоимость товара


#### Интерфейс IBuyer
Описывает структуру данных покупателя необходимых для оформления заказа.

Поля интерфейса:
  payment: TPayment; - Способ оплаты
  email: string; - Электронная почта покупателя
  phone: string; - Номер телефона покупателя
  address: string; - Адрес доставки

#### Тип TPayment
TPayment — тип, определяющий способ оплаты:
- `card` — банковская карта;
- `cash` — наличные;
- `''` — способ оплаты не выбран.

### Модель данных

#### Класс ProductCatalog
Класс отвечает за хранение и управление данными каталога товаров, а также за хранение выбранного товара для отображения подробной информации.

Конструктор:
constructor() - не принимает параметров.

Поля класса:
products: IProduct[] - массив всех товаров каталога.
selectedProduct: IProduct | null - выбранный товар для подробного просмотра.

Методы класса:
setProducts(products: IProduct[]): void - сохранение массива товаров.
getProducts(): IProduct[] - получение массива товаров из модели.
getProduct(id: string): IProduct | undefined - получение одного товара по его id.
setSelectedProduct(products: IProduct): void- сохранение товара для подробного отображения.
getSelectedProduct(): IProduct | null - получение товара для подробного отображения.

#### Класс Basket
Класс отвечает за хранение и управление товарами, выбранными покупателем для покупки.

Конструктор:
constructor() - не принимает параметров.

Поля класса:
items: IProduct[] - массив товаров, выбранных покупателем для покупки.

Методы класса:
getItems(): IProduct[] - получить массив товаров, которые находятся в корзине.
add(product: IProduct): void - добавление товара, который был получен в параметре, в массив корзины.
remove(product: IProduct): void - удаление товара, полученного в параметре из массива корзины.
clear(): void - очистка корзины.
getTotal(): number - возвращает общую стоимость товаров в корзине.
getCount(): number - возвращает количество товаров в корзине.
has(id: string): boolean - проверка наличия товара в корзине по его id, полученного в параметр метода.

#### Класс Buyer
Класс отвечает за хранение, изменение и проверку данных покупателя, необходимых для оформления заказа.

Конструктор:
constructor() - не принимает параметров.

Поля класса:
payment: TPayment - выбранный способ оплаты.
address: string - адрес доставки.
email: string - электронная почта покупателя.
phone: string - номер телефона покупателя.

Методы класса:
setData(data: Partial<IBuyer>): void - сохраняет или обновляет данные покупателя. Возможно изменение как всех полей, так и отдельных полей без потери остальных данных.
getData(): IBuyer - получение всех данных покупателя;
clear(): void - очистка данных покупателя;
validate(): Partial<Record<keyof IBuyer, string>> - проверяет заполненность данных покупателя и возвращает объект с сообщениями об ошибках для незаполненных полей.

### Слои коммуникации

#### Класс WebLarekApi
Класс отвечает за взаимодействие приложения с сервером интернет магазина. Использует переданный в конструктор экземпляр класса Api для получения с сервера объекта с массивом товаров с помощью метода get, и отправки на сервер данных о покупателе при помощи метода post.

Конструктор:
constructor(api: IApi) - принимает объект, реализующий интерфейс IApi, для выполнения запросов к серверу.

Поля класса:
api: IApi - объект класса Api, используемый для отправки GET и POST запросов.

Методы класса:
getProducts(): Promise<IProductResponse> - выполняет GET-запрос на эндпоинт /product/ и возвращает объект с общей информацией о товарах и массивом товаров.
createOrder(order: IOrder): Promise<IOrderResponse> - выполняет POST-запрос на эндпоинт /order/, передаёт данные покупателя и выбранных товаров и возвращает объект с результатом оформления заказа, содержащий идентификатор заказа и его итоговую стоимость.

### Слой Представления (View)
Слой View отвечает за отображение данных приложения и обработку действий пользователя. Компоненты View не содержат бизнес-логику и не взаимодействуют напрямую с моделями данных. При действиях пользователя компоненты генерируют события, которые обрабатываются Presenter.

Все компоненты представления наследуются от базового класса Component, который предоставляет общую функциональность для работы с DOM.

#### Класс Header
Отвечает за отображение шапки сайта.
Содержит кнопку открытия корзины и счётчик количества товаров.

Поля:
counterElement: HTMLElement — элемент, отображающий количество товаров в корзине.

Методы:
set counter(value: number) — устанавливает количество товаров в корзине.

События:
basket:open — генерируется при нажатии на кнопку корзины.

#### Класс Gallery
Отвечает за отображение каталога товаров на главной странице.
Gallery управляет контейнером, в котором размещаются карточки товаров. За отображение отдельной карточки отвечает компонент CardCatalog.

Поля:
catalogElement: HTMLElement — DOM-элемент, в котором отображаются карточки товаров каталога.

Методы:
set items(value: HTMLElement[]) — устанавливает переданные карточки товаров в catalogElement.

#### Класс Card
Базовый класс для отображения карточки товара.
От класса Card наследуется класс CardImage, который расширяет функциональность карточки для работы с категорией и изображением. CardBasket наследуется непосредственно от Card.
В родительский класс вынесена общая функциональность для работы с данными карточки.

Поля:
titleElement: HTMLElement — элемент названия товара.
priceElement: HTMLElement — элемент цены товара.

Методы:
set title(value: string) — устанавливает название товара.
set price(value: number | null) — устанавливает цену товара.

#### Класс CardImage
Базовый класс для карточек, отображающих категорию и изображение товара.
Наследуется от класса Card.
Используется в CardCatalog и CardPreview.

Методы:
set category(value: string) — устанавливает категорию товара.
set image(value: string) — устанавливает изображение товара.

#### Класс CardCatalog
Отвечает за отображение карточки товара в каталоге.
Наследуется от класса CardImage.
Используется для отображения товара в каталоге на главной странице.

События:
card:select — генерируется при нажатии пользователя на карточку товара. В событие передаётся информация о выбранном товаре.

Presenter обрабатывает событие и открывает подробную информацию о выбранном товаре.

#### Класс CardPreview
Отвечает за отображение подробной информации о выбранном товаре.
Наследуется от класса CardImage.
Используется для отображения карточки товара в модальном окне.

Поля:
descriptionElement: HTMLElement — элемент, содержащий описание товара.
buttonElement: HTMLButtonElement — кнопка действия с товаром в корзине.

Методы:
set description(value: string) — устанавливает описание товара.
set button(value: string) — устанавливает текст кнопки действия.

События:
card:button — генерируется при нажатии на кнопку действия с товаром. Presenter определяет, нужно добавить товар в корзину или удалить его.

#### Класс CardBasket
Отвечает за отображение товара в корзине.
Наследуется от класса Card.
Используется для отображения списка товаров, добавленных в корзину.

Поля:
indexElement: HTMLElement — элемент, отображающий порядковый номер товара.
deleteButton: HTMLButtonElement — кнопка удаления товара из корзины.

Методы:
set index(value: number) — устанавливает порядковый номер товара в корзине.

#### Класс Basket

Отвечает за отображение содержимого корзины.
Компонент отображает список выбранных товаров, их общую стоимость и кнопку перехода к оформлению заказа.

Поля:
listElement: HTMLElement — контейнер для карточек товаров.
totalElement: HTMLElement — элемент отображения общей стоимости товаров.
orderButton: HTMLButtonElement — кнопка перехода к оформлению заказа.

Методы:
set items(value: HTMLElement[]) — устанавливает список карточек товаров.
set total(value: number) — устанавливает итоговую стоимость товаров.

События:
basket:order — генерируется при нажатии на кнопку оформления заказа.

#### Класс Form
Базовый класс для работы с формами приложения.
От класса Form наследуются OrderForm и ContactsForm.
В родительский класс вынесена общая функциональность работы с состоянием формы, ошибками и пользовательскими изменениями.

Поля:
submitButton: HTMLButtonElement — кнопка отправки формы.
errorsElement: HTMLElement — элемент отображения ошибок валидации.

Методы:
set valid(value: boolean) — устанавливает состояние доступности кнопки отправки формы.
set errors(value: string) — отображает сообщение об ошибке.

#### Класс OrderForm
Отвечает за отображение формы оформления заказа.
Наследуется от класса Form.
Форма содержит выбор способа оплаты и поле адреса доставки.

Поля:

addressInput: HTMLInputElement — поле ввода адреса доставки.

Методы:
set payment(value: TPayment) — устанавливает выбранный способ оплаты.
set address(value: string) — устанавливает адрес доставки.

События:
order:payment — генерируется при выборе способа оплаты.
order:input — генерируется при изменении адреса.
order:submit — генерируется при отправке формы.

#### Класс ContactsForm
Отвечает за отображение формы контактных данных покупателя.
Наследуется от класса Form.
Форма содержит поля электронной почты и номера телефона.

Поля:
emailInput: HTMLInputElement — поле ввода электронной почты.
phoneInput: HTMLInputElement — поле ввода номера телефона.

Методы:
set email(value: string) — устанавливает адрес электронной почты.
set phone(value: string) — устанавливает номер телефона.

События:
contacts:input — генерируется при изменении email или телефона.
contacts:submit — генерируется при отправке формы.

#### Класс Success
Отвечает за отображение содержимого шаблона успешного оформления заказа.
Success является самостоятельным компонентом View. Он не наследуется от Modal, но может быть помещён внутрь модального окна в качестве его содержимого.

Поля:

Методы:
set total(value: number) — устанавливает сумму заказа, отображаемую пользователю.

События:
success:close — генерируется при нажатии пользователя на кнопку закрытия сообщения об успешном оформлении заказа.

#### Класс Modal
Отвечает за отображение модального окна.

Поля:
contentElement: HTMLElement — контейнер для содержимого модального окна.
closeButton: HTMLButtonElement — кнопка закрытия модального окна.

Методы:
set content(value: HTMLElement) — устанавливает содержимое модального окна.
open() — открывает модальное окно.
close() — закрывает модальное окно.

### События приложения

Для взаимодействия между Model, View и Presenter используется `EventEmitter`.

#### События View

| Событие           | Источник       | Назначение                   |
| ----------------- | -------------- | ---------------------------- |
| `card:select`     | `CardCatalog`  | Выбор товара для просмотра   |
| `card:button`     | `CardPreview`  | Действие с товаром в корзине |
| `basket:remove`   | `CardBasket`   | Удаление товара из корзины   |
| `basket:open`     | `Header`       | Открытие корзины             |
| `basket:order`    | `Basket`       | Переход к оформлению заказа  |
| `order:payment`   | `OrderForm`    | Выбор способа оплаты         |
| `order:input`     | `OrderForm`    | Изменение адреса             |
| `order:submit`    | `OrderForm`    | Переход к форме контактов    |
| `contacts:input`  | `ContactsForm` | Изменение email или телефона |
| `contacts:submit` | `ContactsForm` | Отправка заказа              |
| `success:close`   | `Success`      | Завершение оформления заказа |

#### События Model

| Событие            | Model            | Назначение                    |
| ------------------ | ---------------- | ----------------------------- |
| `catalog:changed`  | `ProductCatalog` | Изменение каталога товаров    |
| `product:selected` | `ProductCatalog` | Выбор товара                  |
| `basket:changed`   | `Basket`         | Изменение содержимого корзины |
| `buyer:changed`    | `Buyer`          | Изменение данных покупателя   |

#### События, используемые Presenter

Presenter подписывается на события View и Model и выполняет необходимую бизнес-логику:

* получает товар из `ProductCatalog` после `card:select`;
* добавляет или удаляет товар из `Basket` после `card:button`;
* открывает корзину после `basket:open`;
* удаляет товар после `basket:remove`;
* открывает форму заказа после `basket:order`;
* обновляет данные `Buyer` при изменении формы;
* проверяет данные покупателя и управляет состоянием кнопок форм;
* переходит к форме контактов после `order:submit`;
* отправляет заказ через `WebLarekApi` после `contacts:submit`;
* отображает результат заказа в `Success`;
* очищает `Basket` и `Buyer` после завершения заказа.

#### События валидации

Presenter формирует результаты валидации данных и передаёт их соответствующим View:

| Событие               | Назначение                                           |
| --------------------- | ---------------------------------------------------- |
| `order:validation`    | Передача результата проверки способа оплаты и адреса |
| `contacts:validation` | Передача результата проверки email и телефона        |
